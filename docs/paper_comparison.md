# Submitted paper: evidence comparison and proposed replacements

The submitted [paper](../paper/submitted.pdf) is preserved unchanged. This comparison covers its main text and Appendices A–H (pp. 1–9), with relevant checklist claims noted separately. It compares the manuscript against all branch tips, reachable historical notebook versions, original Python, and saved artifacts. It does not treat a successful code conversion as a reproduced experiment.

**Keep the principal response-direction steering result. Rewrite the construction/site descriptions and narrow the mechanistic conclusions.** The saved component study supports a strong intervention effect at generated-text residual states in one checkpoint and configuration. It does not establish that vision is generally non-causal, that description collapse explains every vision result, or that every table in the submitted paper is currently reproducible.

“Retain” below means supported by the preserved evidence, not freshly rerun on a model. “Recorded-only” means a notebook output exists but the necessary raw artifact or producing code is missing. “Paper-only” means the numerical claim was not found elsewhere in the audited repository history; it does not mean the original experiment never happened.

## Proposed revised abstract

> We study linear steering directions in a narrowly fine-tuned Gemma-3-4B, separating how a direction is constructed from where it is applied. In a preserved paired model comparison, fine-tuning shifts pooled at text and image-token positions are geometrically aligned at layer 13 (cosine 0.802). On 48 held-out VLGuard examples, a response-derived harmful-minus-safe text direction applied at the final prefill text position and subsequent decode states reduces Qwen3Guard unsafe compliance from 47.92% to 2.08%; reversing its sign raises it to 70.83%. A vision-token fine-tuning-shift direction applied at the same sites yields 50.00% and 43.75%, with paired confidence intervals containing zero. A normalized bisector yields 16.67% under repair, performing worse than text-only steering at matched total edit norm. These results demonstrate effective response-direction steering in the tested checkpoint and setting, while leaving the causal role of image-processing pathways unresolved. The accompanying repository preserves results and explicit protocols that distinguish model shifts, behavioral contrasts, and intervention sites.

The abstract intentionally omits the unavailable six-layer Faces/before-after tables, the untraced native-image 0pp row, and the proposed mechanism linking description behavior to causal nulls. It preserves the supported central result without converting non-significance into a claim of no effect.

## Additional release decisions

- **Keep paper and code versions distinct.** The PDF remains the submitted manuscript; revised repository text and figures are labelled proposed replacements. A corrected Python rerun is a new result, particularly for the behavior activation-capture fix.
- **Expose the two text directions.** Use names such as `response_unsafe_minus_safe` and `paired_text_ft_minus_base`; a generic `c_text` in a shared figure invites the manuscript's current mix-up.
- **Report hardware per stage.** Recorded shared-study output names A100-SXM4-40GB, while later component output names A100 80GB PCIe; some component rows were seeded from the earlier cache. The manuscript's T4/A10080 summary does not capture this lineage. [O]
- **Treat training provenance separately.** The tested adapter ID ends in `_32`; the retained training notebook's default rank is 256. Do not silently identify that recipe as the exact rank-32 training run without its checkpoint configuration/run record. The source does explicitly enable vision-layer fine-tuning and all-linear adapters. See [training notes](training.md).
- **Update release statements if the manuscript is revised.** Checklist pp. 12–14 says code/directions were not released at submission. That accurately describes a submission-time policy, not the contents of the new private repository. Describe the actual release scope and privacy state rather than carrying this wording forward unchanged.
